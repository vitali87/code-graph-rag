code-graph-rag now requires its Rust extension, `cgr-graph-rs`, on every platform, and no longer runs without it: `import codebase_rag` stops with an error that says how to get it. The extension ships as wheels for CPython 3.12 or newer on Linux x86_64 and aarch64 (glibc and musl), macOS (Intel and Apple silicon) and Windows x64. On any other platform (PyPy, 32-bit or other architectures such as armv7, s390x and ppc64le, Windows on ARM), installing code-graph-rag now fails, where it used to install and run the pure-Python engine.

There is no setting that keeps the old behaviour on those platforms. To keep using cgr there, pin `code-graph-rag` below this release.

Existing installs on the supported platforms already have the extension and see no change in behaviour. They install fewer packages: `defusedxml` and `tomli-w` are gone (cgr reads XML project files and writes workspace files in the extension now), and `huggingface-hub`, with `hf-xet`, `fsspec`, `tqdm`, `filelock` and `packaging`, is installed only by the `semantic` extra, the one part of cgr that uses it. See [The Rust extension](https://docs.code-graph-rag.com/architecture/embedded-graph/#the-rust-extension).
