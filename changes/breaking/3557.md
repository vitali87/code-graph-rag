The MCP server and the agent's file tools refuse three things they used to do:

- No file tool writes inside a `.git` directory any more, in the CLI or over MCP. Git runs the commands its config and hooks name, so a write there could run code on your machine. Change git's own files with git.
- MCP `write_file` and `surgical_replace_code` no longer change files that look like credentials (`.env`, `.env.*`, private keys, `.aws/credentials`, and the rest of the list MCP `read_file` already refuses). `.env.example` and other templates are still written. To keep the old behaviour, export `CGR_ALLOW_SENSITIVE_WRITES=true` in the environment the server starts with (a `.env` file cannot set it). The CLI agent already asks before every write and is unchanged.
- `cgr mcp-server` no longer starts in a directory that holds your home directory, or in a disk root such as `/`, unless `TARGET_REPO_PATH` names it. A client that launches the server without `TARGET_REPO_PATH` from such a directory now gets a configuration error at start-up. Set `TARGET_REPO_PATH` to the project's directory in the client's server configuration, as the MCP setup guide shows.

The HTTP transport without `MCP_HTTP_AUTH_TOKEN` now also refuses requests whose `Host` or `Origin` header names anything other than `127.0.0.1`, `localhost` or `[::1]` on the server's port. Local clients are unaffected. With a token nothing changes.

Existing installs: a server configured with `TARGET_REPO_PATH` set to a project, as the setup guide shows, starts as before. See [Credential files](https://docs.code-graph-rag.com/architecture/security/#credential-files) and the [MCP server guide](https://docs.code-graph-rag.com/guide/mcp-server/).
